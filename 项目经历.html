AI 工作平台（本地 AI 对话工作平台）

全栈开发

个人项目 · Next.js 16 + React 19 · 本地优先（Local-first）

基于 Next.js 16（App Router）+ React 19 构建的本地优先 AI 对话工作平台。 模型默认优先接入本地 Ollama（OpenAI-compatible 接口），本地服务不可用时自动 fallback 到 DeepSeek； 集成多会话管理、本地工具调用、文件 / 对话 RAG、语义与全文搜索、上下文压缩和开发问题文档系统， 所有结构化数据与向量嵌入均存储在本地，不上传云端。

技术栈
Next.js 16 (App Router) React 19 TypeScript（严格模式） OpenAI-compatible SDK Ollama (qwen2.5-coder:7b) DeepSeek (fallback) better-sqlite3 / SQLite FTS5 Xenova/all-MiniLM-L6-v2 IndexedDB react-virtuoso Tailwind CSS 4 + CSS Modules
核心工作与亮点
  • 本地优先 LLM 架构：通过统一的 OpenAI-compatible provider 实现「Ollama 本地优先 + DeepSeek 自动 fallback」， 本地可用时零云端依赖，失败时无缝降级，并对缺失配置返回明确的 503。
  • 本地工具调用（Tool Use）：实现 search_documents / search_conversation / search_uploaded_files 三类工具，服务端在决策阶段注入专门 tool-use 指令、限制最多 2 轮调用， 工具结果以统一 sourceType + 片段字段结构化返回，减少误调与漏调。
  • 双路 RAG 检索：浏览器端单例复用 MiniLM 嵌入模型，对上传文件（按行 20/3 分块）与对话历史分别做向量检索， Top-K + 相似度阈值过滤后作为 system 消息注入上下文；嵌入结果持久化到 IndexedDB，切换会话无需重算。
  • 语义搜索 + 全文搜索：会话消息支持向量语义搜索并可一键跳转（配合虚拟化列表）； 文档侧基于 SQLite FTS5 实现覆盖标题/标签/问题/解决方案/代码正文的全文检索。
  • 开发问题文档系统：从对话中用 LLM 自动提取标题、分类、标签、问题、解决方案与代码，归档为结构化文档， 支持分类浏览、全文检索、编辑与「文档 ↔ 原始对话」双向关联。
  • 上下文管理：首轮对话自动生成会话标题；长对话可手动压缩为摘要（保留最近 3 轮、最多携带 15 轮上下文）， 兼顾连贯性与 token 成本。
  • 本地持久化与工程化：基于 better-sqlite3 设计规范化 schema（外键约束、WAL）， 首次启动自动迁移旧版 localStorage 数据；后台嵌入索引通过 FIFO 任务队列串行执行； 超过 30 条消息启用 react-virtuoso 虚拟滚动。全程 TypeScript 严格模式、功能按最小变更（minor-change）拆分实现。
